Building Production-Grade Chrome Extensions

July 2026

Why Most Extensions Never Pass Review

Every year, thousands of extensions are rejected from Chrome Web Store. Top reasons: excessive permissions, poor privacy practices, missing documentation.

1. Permission Minimization

  • Use activeTab instead of tabs — Temporary access only when user clicks
  • Use scripting + activeTab instead of <all_urls> — Inject on-demand
  • Document every permission — Explain in store listing
{{ "permissions": ["activeTab", "scripting", "storage"] }}

2. Service Worker Resilience

// WRONG — cleared on termination
setTimeout(() => doSomething(), 60000);

// CORRECT — survives termination
chrome.alarms.create('myAlarm', {{ periodInMinutes: 1 }});
chrome.alarms.onAlarm.addListener((alarm) => {{
  if (alarm.name === 'myAlarm') doSomething();
}});

3. Offscreen for DOM Operations

async function copyImageToClipboard(dataUrl) {{
  await chrome.offscreen.createDocument({{
    url: 'offscreen.html',
    reasons: ['CLIPBOARD'],
    justification: 'Copy image to clipboard'
  }});
  await chrome.runtime.sendMessage({{ type: 'OFFSCREEN_COPY', dataUrl }});
}}

4. Dynamic Content Script Injection

chrome.action.onClicked.addListener(async (tab) => {{
  await chrome.scripting.executeScript({{
    target: {{ tabId: tab.id }},
    files: ['content.js']
  }});
}});

5. i18n for Global Reach

// manifest.json
{{ "default_locale": "en", "name": "__MSG_extName__" }}

// _locales/en/messages.json
{{ "extName": {{ "message": "My Extension" }} }}

// _locales/zh_CN/messages.json
{{ "extName": {{ "message": "我的扩展" }} }}

6. Store Listing Best Practices

  • Screenshots: 1280×800px, show extension in action
  • Description: First 2 lines are critical for search
  • Privacy policy: Required for any data-handling extension
